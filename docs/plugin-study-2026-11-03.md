## 1. syyr1987/dsh-linghun（灵魂）

来源：README（11.3 KB，master 分支）+ **源码**（`memory.js` 16 KB、`ontology.js` 4.9 KB，2026-11-03 补读）。

学到的东西：

1. **「收口者（Closer）」**：作者观察到 agent 的通病是「一直计划、落地为零」，于是补一个专门负责收口的角色——直觉给候选，判断给结论，动作必须落到一个终结状态。**这条正打我们的痛点**：`autonomy.json` 里 10 个目标全是 `done`，因为三步（读/记/交接）一轮就跑完，等于没有收口。
2. **判断纪律「最小可用三条」**：不核实不下结论；能验证的才断言。跟我们 judge 的「拿不准就不写」同路，但他们强调「先核实」。
3. **认知环**：判断有出处、反馈有归因、改进有链条。我们的 traits 有 `ref`，但没有「这条认知后来被哪次对话验证/推翻」的链。
4. **海马体三层**：热缓冲（最近事实）→ 巩固 → 冷抽象。我们只有两层（原话记忆 + traits），中间缺「巩固」这一层。
5. **按置信度遗忘**：每条记忆带 high/medium/low，遗忘按置信度算。我们只有 importance + 时间衰减，没有置信度标签。
6. **自我进化**：agent 能读写自己的灵魂卡（`soul_read`/`soul_update`）。我们的自我模型是只读生成的，agent 不能改。

## 2. s867968286/dsh-companion（伙伴）

来源：README（13.6 KB，master）+ **源码**（`src/memory-store.mjs` 11 KB、`src/tools.mjs` 6.8 KB，2026-11-03 补读）。

学到的东西：

1. **用 Markdown 定义伙伴**：身份/性格/准则/记忆都是文件，人在文件里改，agent 在对话里改。我们的内核也是文本，但没做成可直接编辑的文件。
2. **自动日记 + 自动记忆更新**：和我们日记/判断卡的分工相近。
3. **一个真实的工程坑**：从 dsh 0.1.7-rc.2 起 preset 只能由已安装 bundle 声明，官方不再读 `.agent-presets/` 目录；他们选择文件即插即用，代价是伙伴不出现在官方预设选择器里。**我们不用踩**：我们是 bundle 安装。
4. **工具白名单要写精确名**：他们本地只能读到全局层名单，用通配过滤会误杀预设层工具（read/write/web_search）。我们的 `toolgate` 也有类似白名单，值得自查一遍是不是只看全局层。

## 3. Kaalia0912/dsh-whale-musume-persona（鲸鱼娘人设）

来源：README（1.9 KB，main），未读源码。

学到的东西：

## 补读源码（2026-11-03 下午）

上面那些结论是读 README 得出的。被主人点了一句「你不读下代码？」之后补读了两个仓库的核心文件。
**结论：README 讲的是设计，代码里才有真东西——有三条是 README 里完全没有的。**

### syyr1987/dsh-linghun（`memory.js` / `ontology.js`）

1. **「已翻转」是独立状态，不是分数**。置信度四档 `high/medium/low/wrong`，`wrong` 不是最低分，而是
   「这条被推翻过」——注入时**直接排除**，渲染时加【已翻转·勿引用】。我们的 `confidence` 是 0–1 数值，
   表达不了「确认是错的」和「只是不确定」的区别。这一条直接可用。
2. **注入排序里 high 不参与时间衰减**：验证过的知识保持写入序常驻，medium/low 才按 `last_access` 沉底。
   我们是一套半衰期管所有记忆——久未使用的高置信事实会被时间和低置信事件一起挤掉。
3. **记忆条目是人可读的 Markdown 块**，元数据藏在 HTML 注释（`<!-- last_access -->`）和标题行里。
   人能直接改，模型也能读；我们的 JSON 结构对模型不友好，只能靠代码拼。
4. **巩固只压「一行 60 字锚点」**，冷储不倾倒原文；截断按条目边界切，不切在字符中间（`truncateKeepHead`）。
   我们的 `consolidatePeer` 是词频摘要（`a、b、c（N 条旧事）`），信息量比「每条一行要点」薄。
5. **本体投影**（`ontology.js`）：主题节点 + 别名命中优先、BM25 兜底，是 BEAM 实验里 60→85/90 的关键一环。
   我们有 df 词频，但没有「主题」这一层。

### s867968286/dsh-companion（`src/memory-store.mjs` / `src/tools.mjs`）

1. **写盘三件套**，README 里只提过一句：原子写（tmp + rename）、**同路径 enqueue 串行**、先写 changelog 再改文件。
   这正打我们今天踩的坑——`addMemory` 之后必须重读才能改旧条，否则把刚写的摘要盖掉。他们的答案是
   「所有写操作进队列」，我们是「人肉记得重读」。**这是今天最该抄的一条。**
2. **为什么必须走工具、不让模型直写文件**：直写绕开队列（读-改-写竞态、last-write-wins）、没有 changelog、
   没有校验。理由写成了文件头注释——这种「为什么不让它这么干」的记录，比功能说明有用。
3. **`old_text` 必须逐字且全文唯一**，出现多次直接拒绝，报错还带补救提示（「先读文件取一段唯一原文」）。
   我们的 `correctMemory` 用 `includes(kw)` 匹配第一条——正是他们拒绝的那种写法。
4. **换行风格检测（CRLF/LF）**：内部按 LF 处理，写回还原原风格，否则 Windows 用户一次写入就整文件 diff 爆炸。细但真实。
5. **可编辑文件白名单写死在代码里**（`IDENTITY/SOUL/USER/MEMORY.md`，`SYSTEM.md`/`AGENTS.md` 不在内）。
   权限边界不是配置项，是常量。

### 我们准备怎么用（不抄代码）

| 借的点 | 怎么落 | 取舍 |
|---|---|---|
| 「已翻转」独立状态 | `memory` 的 `confidence` 之外加 `status: overturned`，注入排除 | 要迁移老数据，先只读不写 |
| high 不参与衰减 | `confidence >= 0.85` 的条目半衰期不衰减（或极长） | 防「久未用的真事实沉底」 |
| 写操作串行化 | 给 `store.writeJson` 加按路径队列，替掉「人肉重读」 | 改动面大，先做 memory/traits |
| 巩固压成「每条一行」 | `consolidatePeer` 从词频改成「每条取首句 40 字」 | 需处理长条目 |
| 主题节点 | 先不做，等 BM25/df 的召回真不够用再说 | 明确不做：没有 BEAM 那种评测集，别拍脑袋加层 |

**明确不学**：Markdown 当记忆存储（我们的 JSON + 双卡已经够用，换存储的收益不抵迁移风险）。
