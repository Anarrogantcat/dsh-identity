# dsh-qqbot-refine 完整方案（NapCat 主线 · 功能不缩水）

> 状态：**方案定稿待批**，不改任何配置/代码。
> 前提：NapCat 小号 690618714（已稳定跑几个月，与 Yunzai 共用）；单群使用；token 有开销。
> 承诺：**NapCat 模式下功能不缩水**——过去因官方通道限制而"降级/放弃"的每一项，这里都给出 NapCat 下的完整实现。
> 同时：**官方模式按能力位明确关掉**拿不到的功能（置灰 + 说明原因），不假装、不半截执行。

## 0. 不缩水承诺（逐条对照）

| 过去的问题 | 过去怎么凑合 | 现在怎么做（不缩水） |
|---|---|---|
| 群名片拿不到，叫错人名 | 用 QQ 昵称，错了就错了 | OneBot 事件自带 `sender.card`；`get_group_member_list` 无限流随时刷新 |
| 成员信息 30 QPM | 改成读事件里的 role，缓存 | 直接调成员接口，实时刷新；画像/群管都准 |
| 真实用量（元）拿不到 | 退化成"闸门计数" | 读 dsh-onebot 的 `chat-sessions.json` → 拿到 chat↔DSH session → 读 projcache `tokenUsage` → **真实 token + 金额**（官方通道也保留同一套） |
| 撤回 / 戳一戳 / 合并转发收不到 | 不做 | 全部接：撤回不回答、被戳有反应、合并转发能读能发 |
| 图片靠签名链接 | 打补丁修 DNS | NapCat 给本地 file/url，直接读；补丁只在官方通道需要 |
| 主动消息额度 | 靠频率闸压 | 本地发送无额度，只受我们的安全模式约束 |
| 表情收集受链接过期影响 | 收得少 | 本地文件直收，收集率提升；自动按尺寸筛 + 模型打标 |
| 分段发送 | 自己实现 | 它自带按句切 → **关掉我们的重复实现，保留可配置**（不是缩水，是去重） |

### 1.5.3 代码怎么用（不给"半截"功能）

```js
// 每个新功能挂能力位，缺失就整块跳过（不是部分执行）
export function guardCap(cap, fn) {
  return (...args) => {
    if (!caps().has(cap)) {
      audit('capability.skip', { cap, mode: modeOf() })
      return { skipped: true, reason: `当前模式（${modeOf()}）不支持 ${cap}` }
    }
    return fn(...args)
  }
}
```

- 入站事件：官方模式不注册「撤回/戳/转发/表情」四个处理器（注册了也收不到）
- 出站：引用回复在官方模式降级为普通文本（**明确**，不假装）
- 面板：能力位驱动的置灰 + tooltip（例如：群名片 →「NapCat 模式专属」）

### 1.5.4 模式切换时的自检

切换后启动时打印并写审计：

```
[capability] mode=onebot  可用 15/15
[capability] mode=tencent 可用 7/15 · 缺失：群名片/成员列表/撤回/戳/转发/表情/引用/视频/STT
```

并在面板「通道」页列出缺失项与原因（避免你以为功能坏了）。

## 4. 花费硬闸（不缩水的关键一环）

### 4.1 真实用量怎么拿（官方/OneBot 都行）

```
OneBot:  <media dir>/chat-sessions.json  →  chatId ↔ DSH sessionId
          →  <DSH_HOME>/storages/session_projcache/sessions/<sid>.json
          →  record.rows.tokenUsage.val.totals
          →  单价折算 → 金额
官方:      appId + group openid → sid（sha256 推导）→ 同上
```

> 实测：dsh-onebot 把映射存在它的 media 目录（`chat-sessions.json`，文件名为常量，尚未生成因为插件未挂载；挂载后即时可读）。

### 4.2 硬闸行为

```yaml
usage:
  dailyYuanHardLimit: 2.0
  onExceed: degrade        # degrade | mute
  warnAt: 0.8              # 80% 时先提醒一次
```

- 检查点：**每次调用模型之前**（0 token 成本）
- degrade：闲聊只回一句模板（0 token）；命令/面板照常
- mute：静默到次日零点
- 面板显示：今日金额 / 上限 / 剩余 / 超限原因

## 9. 风险与回滚

- 封号：安全模式 + 熔断 + 单群 + 小步试跑（见《迁移方案》14 节）
- 协议漂移：官方通道保留，改一个值切回
- 迁移不可逆：所有迁移先备份 + 得 run 预演
- 我们对第三方包的包装/补丁：写进文档，升级后重打
