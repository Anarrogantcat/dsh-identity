# 2026-11-03 这一天学到的东西

都是从真事故里抠出来的，不是总结陈词。每条写清「事故现场 / 教训 / 下次怎么防」。

---

## 1. 开关要写清「只影响哪一层」

**现场**：`frequency.workMode` 是为了「别让精力影响写插件」加的。实现写成了
`workMode ? '精力只当状态记着' : pace.toneHint(tone)`——一句替换，把整个语气分档抹掉了。
「会累」从聊天里整个消失，而面板上还显示「精力：7%」，看起来一切正常。

**教训**：为某个场景加的开关，不该变成全局总闸。`workMode` 应该只压「干活力度」（别省工具、别缩短输出），
不该压「说话方式」（累了话短是人格的一部分）。

**下次怎么防**：加开关时先写下它**不影响**什么，再写影响什么；测试里断言「开关打开时，另一层仍然按原样变化」。

---

## 2. 读状态要带结果语义

**现场**：共情提示只取「最近一条」，不看 `outcome`。对方说了「别安慰我」，`noteOutcome` 已经标了
`negative`，下一轮还是把「先接住情绪」塞进提示词——安慰被拒了还接着安慰。

**教训**：「最近一条」不等于「该给的那条」。记录下来的状态，读的时候要连它的结果一起读。

**下次怎么防**：凡是「取最新一条」的地方，问一句「这条要是被否决了还该用吗」；`promptFor()` 这类
「注入专用」的读取函数，把过滤规则收在里面，别散在调用点。

---

## 3. 打分和阈值会静默吞东西

**现场**：记事验收，5 个 peer 池子里有 3–18 条「关于这个人」的记忆，注入只出 0–1 条。
不报错、不告警，只是老条目鲜活度低、分数过不了 `injectFloor`，`pickInject` 直接返回空。
表现出来就是「记得一堆事，却说不出对方是谁」。

**教训**：**悄悄不记得，比报错更难查**，因为它看着一切正常。纯靠分数的通道，一定要给重要类别留保底。

**下次怎么防**：重要的东西（人物、承诺、教训）不跟事件抢分数，单独走保底；保底规则写测试，
断言「池里有 3 条就必须注入 3 条」，而不是「平均分够高」。

---

## 4. 验收必须用真数据跑

**现场**：判断卡记人、记事注入这两项，夹具测试全绿；一拷真实数据跑，一个只有 75% 轮次达标（还是把
压缩摘要误算成判断卡），一个注入 0–1 条。两个真 bug 都是真数据露出来的。

**教训**：夹具证明的是「代码自洽」，不是「线上对」。真实数据的分布、时间跨度、脏数据，夹具模拟不出来。

**下次怎么防**：每个验收项配一个「拿真数据跑」的命令或脚本（如 `scripts/judge-quality.mjs`），
跑之前把数据拷到临时目录，不碰线上。

---

## 5. 测试自己也会骗人

**现场**：`memory-person-guarantee-test` 断言「注入的第一条必须是某一句」，但保底按分数排序、同分时顺序会变。
单跑全绿，连跑 6 次挂了 1 次；全套跑也偶发挂。差点被当成真 bug 去改实现。

**教训**：断言写死顺序 = 给自己埋 flaky。偶发的红先怀疑测试，再怀疑实现。

**下次怎么防**：断言写成集合/包含关系（「注入的都是关于人的那几条」），不写「第一条是 X」；
新测试跑 5 次以上确认稳定。

---

## 6. 部署是固定动作，不是顺手

**现场**：这一天改了 7 个版本（1.9.221 → 1.9.227）。宿主侧 js 每次都要重启才生效，
而 `check-version` 只对 104 个 js 的一致性负责，不对「进程是否加载」负责。

**教训**：改宿主侧 → 部署 → `check-version` 一致 → 重启 → 再确认版本号。少一步就会出现
「代码是新的，跑的是旧的」。

**下次怎么防**：交付时说清「要重启」还是「刷新就行」，别让主人猜；重启后先跑一次 check-version 再报完成。

## 一句话版

- 开关只影响它该影响的那层
- 读状态要读结果
- 打分不能吞掉重要的人
- 夹具绿 ≠ 线上对
- 断言别写死顺序
- 改宿主侧就要重启，重启完再确认

最想记住的是第 3 条：**悄悄不记得，比报错更难查**。
