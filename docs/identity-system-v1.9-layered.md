> 状态：设计定稿；P0 治理内核、P0.5 接线、P1 身份核心、P2 接续包、P3 日记、P4 承诺/反思已进仓库（未部署 DSH）。

> v1.11：**接线契约 + 竖切验收 + 门禁**——保证功能真的生效、互通、回环，不残缺。
> v1.12：**零认知依赖定死**——agentPresets / feiyu-mood 是过渡口子，P1 结束清零。
> v1.13：**P0.5/P1 落地修正**——接线扫描进 CI；身份段 900 字只算「人格」，记忆/认知/标记属上下文段单独预算；`agentPresets`/`feiyu-mood` 已删。

## 0. 怎么读 + 分类规则

系统分 **五层 + 三个横切**，每个东西只出现在一个层里：

| 层 | 回答的问题 | 典型内容 |
|---|---|---|
| **L0 基础** | 东西存在哪、怎么记 | 存储、事件流、审计、配置 |
| **L1 身份** | 她是谁、怎么说 | 内核、自我、场景、注入顺序 |
| **L2 认知** | 她记得什么、怎么想、怎么长 | 记忆双卡、日记、反思、承诺、心情、生活参数、成长指标 |
| **L3 治理** | 能不能做、额度、怎么生效、怎么回滚 | 策略、提案/校验/提交、状态分层、预算、调度、支付网关 |
| **L4 能力** | 她会做什么（provider） | 生图、语音、媒体发送、收款码、浏览器、电脑操控、MCP 应用 |
| **L5 通道/交互** | 消息怎么进出、人怎么触发 | QQ/NapCat、Web、命令、自然语言、确认 UX |

**横切**：A 安全隐私 · B 可观测/验收 · C 迁移/测试/阶段。

### 分类规则（以后新增功能照这个放）

1. **能力**（provider）= 一件具体的事，有参数、成本、失败码；
2. **工具**（exposure）= 模型能不能直接调这个能力（默认关，开了也走 L3）；
3. **交互**（UX）= 人怎么触发（命令/自然语言/确认/直出）；
4. **治理** = 能不能做、额度、审计、回滚；
5. **通道** = 消息怎么进出；
6. 同一个能力可以有多个入口，但**只实现一次、只受一套治理**。

> 反例（本版已纠正）：生图曾既像"功能"、又像"工具"、还像"通道命令"。
> 正解：L4 能力 `image.generate` + L5 入口 `#画/自然语言` + L3 策略/额度/审计；工具暴露是可选项。

## 2. L0 基础层

- **存储**：`store.js`（原子写 JSON、append-only JSONL、审计）。
- **事件流**：`events.js`：按 peer/天分段、`seq` 自增、`origin`（inbound/bot/notice/timer）、`ref` 幂等、30 天修剪。
- **配置**：`config.js`（默认值、面板字段、迁移）。
- 原则：**任何重要状态都必须能从磁盘重建**。

---

## 3. L1 身份层

| 子层 | 内容 | 规则 |
|---|---|---|
| 内核 | 名字、物种、价值观、硬边界 | 只 Owner 可改；traits 不能覆盖 |
| 自我 | 偏好/习惯/口癖/边界细节/对人的态度/能力自知 | 证据驱动，≥3 次且跨 ≥2 天才 durable |
| 场景 | 群聊短句/克制/私聊/讲解 | 按群/私聊切换，不改人格 |
| 注入 | 内核→场景→durable traits→关系/情绪→群规→记忆/认知/日记片段 | 稳定在前、易变在后；**身份段** ≤900 字（记忆/认知/标记属上下文段，单独预算；预算不够先裁风格） |

优先级：`安全/内核 > 场景硬规则 > durable traits > 临时情绪 > 风格花活`。

---

## 4. L2 认知层

| 模块 | 职责 | 关键约束 |
|---|---|---|
| 记忆双卡 | 衰减卡进提示词；全量卡只存档 | 半衰期 30/7 天；Top-k ≤300 字；80/90/100% 水位；不硬删 durable |
| 日记 | 每天第一人称 3–6 句 | 素材来自 events；整篇不注入，只给 1 句或按需读 |
| 反思 | 日/周/月复盘、改进项、风格审计 | 只吃事件，不吃自己写的日记（防自我强化） |
| 承诺 | 答应→待办→兑现/逾期→反思 | 接续包必须带未完成承诺 |
| 心情 v2 | 七情六欲、复合情绪、行为映射 | 只改"怎么说"，不改事实/边界/收费/安全 |
| 生活参数 | 作息/节奏/频率等 ~30 项 | 范围内自调；敏感项只读/审批；改完验证；可回滚 |
| 成长指标 | 稳定认知数、矛盾率、兑现率、情绪波动 | 只读汇总，写审计 |

## 5. L3 治理层（所有"生效"都在这）

| 机制 | 作用 |
|---|---|
| 策略存储 | 动作模式（auto/dryrun/confirm/human/off）、限额、白名单；只有 Owner + 确认码可改 |
| 提案→校验→提交 | 模型/能力只产出 proposal；规则引擎校验；独立存储/网关提交 |
| 状态分层 | ephemeral/tentative/durable；冻结检测；到期退休；冲突降级 |
| 自适应预算 | `min(上限, max(保底, 今日花费×share))`；EMA 预估；降级不取消；保底每天一次模板闭环 |
| 调度器 | 来源闸/幂等/租约/退避熔断/限流/单并发/超时；记录跳过原因 |
| 支付网关 | 独立进程；限额/白名单/余额；人持确认码；订单幂等；防重放；台账双写 |

**四个硬问题**：状态不污染、限额聊不掉、临时情绪写不死、支付在模型外。

## 5.5 自主循环（跨 L2/L3/L4 的主循环）

> 目标：**有人味、记得住、靠得住、能独立自主、能学能成长。** 自主不是"失控"，是"在围栏里自己走"。

```
观察（群聊/事件/自己的状态）
 → 好奇/目标（想弄明白什么、想做什么）
 → 计划（几步、用什么能力）
 → 治理（L3：预算/权限/要不要问人）
 → 执行（L4：对话/工具/生活参数）
 → 验证（结果对不对、有没有生效）
 → 记录（L2：日记/经验/承诺）
 → 复盘（哪里没做好、下次怎么改）
 → 调整（改参数/提策略建议）
```

| 自主能力 | 内容 | 边界 |
|---|---|---|
| 好奇队列 | 没弄明白的事、想验证的假设、没答完的话 | 有上限、会过期、按预算执行 |
| 自主目标 | 自己定"今天想做什么" | 只能是小目标；大动作要问人 |
| 自主动手 | 在 L0–L2 范围内自选工具 | 超范围/敏感动作需确认 |
| 自主学习 | 从纠正/失败/接话率更新规则与风格 | 学习结果要验证，不直接改人格 |
| 自主生活 | 生活参数自选、验证、回滚 | 凭据/隐私/预算硬上限不开放 |
| 自主复盘 | 日/周/月回顾，产出改进项并执行 | 吃事件，不吃自己的旧输出 |

**自主等级**（可配，默认 A2）：
A0 只应答 → A1 会主动搭话 → A2 能自主小任务 → A3 能自主目标+用工具 → A4 能自主调生活参数。

**围栏**：改不了内核/限额/钱/隐私；预算自适应；全程审计；`#停手`；可回滚。
**验收**：主动发起率、自主任务完成/验证率、重复犯错率、授权内"没问也能做对"的比例、日均成本。

## 6. L4 能力层（统一契约）

### 6.1 能力契约（所有 provider 同一套）

```json
{
  "id": "image.generate",
  "provider": "comfyui|remote|local|cloud",
  "params": { "…": "schema" },
  "cost": { "kind": "gpu_time|tokens|chars|count", "estimate": "…" },
  "timeoutMs": 240000,
  "failureCodes": ["provider_down", "timeout", "rejected"],
  "policyKey": "image.generate",
  "quota": { "perGroupHour": 3, "perUserDay": 2 },
  "audit": true
}
```

- **只在 L4 实现一次**；L5 只是入口，L3 只管放行与记账。
- 默认最小权限：只读类 auto，写类 confirm，钱类 human。
- 工具暴露（模型直调）是**可选项**，默认关；开了也走 L3。
- 工具侧记忆不进入 L1/L2；工具输出视为不可信内容。

### 6.2 能力清单

| 能力 | 默认 | 说明 |
|---|---|---|
| `image.generate` | 开（群管理可限） | ComfyUI 本地/远程；图生图；角色 auto |
| `voice.synthesize` | 关 | 本地 GPT-SoVITS / 云端 / 现有 TTS；silk |
| `media.send` | 开 | 图片/表情/视频/文件；失败抛错回落 |
| `payment.receive` | 开（限额） | 静态码 + 实时充值码（CDP） |
| `browser.act` | 关 | 登录态 + CDP；L0 读默认 |
| `desktop.act` | read | 电脑操控；点击/打字需 full |
| `mcp.phone` | 关 | 手机 GAgent/OmniClaw；技能记忆留手机 |
| `mcp.bili` | 可开（只读） | B站认知 |
| `mcp.heixia` | 关 | 小黑盒；dry_run 默认 |

### 6.3 生图能力的具体实现口径

- **provider**：ComfyUI（本地 SD1.5 anything-v5）/ 可选远程；工作流 txt2img / img2img；
- **参数**：prompt、negative、宽高、steps、ref、denoise、画风；角色基准由 `character=auto|lock|free` 决定；
- **搜索**：默认关；只在"需要现实参考"时开，2.5s 超时、不阻塞、每日缓存；搜索结果**只用于确认文案，不进图像提示词**；
- **策略/额度**：`policy.actions['image.generate']` + 每群每小时/每人每日；
- **观测**：耗时分解（搜索/排队/生成/总计）、失败码、是否直出；
- **不占认知**：生成的图不进日记/人格；只记事件与 ability trait。

## 7. L5 通道与交互层

### 7.1 通道：QQ / NapCat（OneBot 11）

连接 `ws://127.0.0.1:3001`（token、array 格式、不上报自身消息）；单活切换；15 能力位自检；自动重连/健康/延迟。
入站：群消息→闸门、合并转发展开、引用、撤回不答、戳一戳、表情回应、成员变动、图片→attachment、可选 STT、禁言闭麦、被踢摘名单。
出站：纯文本化、打字节奏、拆条、引用、图片/语音/视频/文件、定时撤回、`#赞`、失败审计+熔断。
群管：`#禁言/#解禁/#踢人/#名片/#撤回/#赞`（Owner/Admin，不假成功）。
接缝：会话 id 稳定（resume）；每群一个场景；群消息→events→日记；表情/接话率→learn；收款码发图。

### 7.2 交互：命令/自然语言/确认 UX

- `#画 [描述]`、@她「画个…」→ 都调 L4 `image.generate`；
- `draw.confirm = always | smart | off`：smart 下明确短句**一句话直出**，歧义先问；`!` 前缀强制直出；
- 直出仍走 L3：权限/额度/审计/冷却，不是绕过；
- 语音/图片/表情的发送同理：L5 触发，L4 执行，L3 放行。

## 7.5 依赖边界：零第三方认知

> 原则：**认知类零依赖；能力类可选；硬依赖只剩 NapCat + DSH 核心。**
> 下面两项是**过渡兼容口子，P1 结束必须清零**（删调用/删配置/数据只读迁移）。

| 项 | 现状 | 为什么还留 | P1 清零动作 |
|---|---|---|---|
| `agentPresets`（宿主预设） | 有就挂，没有就退回宿主默认 | 存量用户可能绑着宿主预设 | ✅ P1：删除调用与配置项，身份段由本地注入 |
| `feiyu-mood/state.json` | 默认不读，仅 `auto/plugin` 时兼容 | 兼容以前配过的人 | ✅ P1：删除读取器与 `auto/plugin` 选项，只留本地 |

**硬依赖**：NapCat（OneBot 11）、DSH 核心服务、Node。
**软依赖（可降级）**：sharp（卡片）、silk-wasm（语音）、ComfyUI/Edge/TTS/ffmpeg/yt-dlp/WSL（对应功能）。
**可选能力**：dsh-computer-use-win、MCP 手机/B站/小黑盒、loop-guard/desktop-guard。
**明确不依赖**：任何人设插件、任何第三方记忆插件、任何第三方心情插件。

## 8. 横切 A：安全与隐私

- 权限：Owner 最高；群友默认不能驱动外部账号/钱包；授权粒度 应用×动作×群；
- 凭据：只存登录态/平台授权（系统密钥链），不存密码/卡号；不入日志/仓库；
- 注入防护：用户文本/工具输出一律当数据；"忽略之前指令"不执行；
- 记忆隔离：工具技能/记忆不进 L1/L2；跨群只搬事件不搬原话；
- 资金：L4-a 入账开、L4-b/c 授权、L4-d 人按；
- 一键停手/冻结；审计可回放。

## 9. 横切 B：可观测与验收

面板按层组织：**身份 · 认知（记忆双卡/日记/反思/承诺/心情/生活参数/成长）· 治理（策略/调度/预算/网关）· 能力（生图/语音/媒体/浏览器/电脑/MCP）· 通道（连接/能力位）**。
命令：`#自我` `#日记` `#成长` `#心情` `#生活` `#能力` `#账号` `#充值码` `#充值` `#饭账` `#余额` `#停手` `#冻结钱包` `#纠正` `#忘记`。

验收要点：身份一致、纠正后少犯、上周可答、承诺可统计、情绪平滑、八股收敛、压缩后不失忆、承诺找回 ≥95%、记忆水位、生活参数可验证可回滚、生图一句话直出且耗时可分解、收款码不重复下单、通道断线恢复、治理注入无效、能力缺失不崩、凭据零泄漏。

## 10. 横切 C：迁移 / 测试 / 阶段

### 10.1 迁移与改名
`dsh-identity`（显示「大肥鱼 · 身份系统」）＋旧名兼容壳；路由别名；数据目录复制迁移（旧留 30 天）；人设拆内核/风格；记忆→双卡；心情 7 维→v2；self→traits；`identity.takeover=false` 回滚。

### 10.2 测试
单元：traits/日记/承诺/心情/预算/调度/八股/能力分级/钱包/登录桥/策略/确认码/生活参数/生图判定。

## 11. 总结

这份方案现在只有**五层**：基础（放东西）、身份（她是谁）、认知（记得/怎么长）、治理（能不能做）、能力+通道（会做什么/怎么进出）。每个功能只有一处归属；生图是**能力**，`#画` 是**入口**，额度与审计归**治理**——不再混淆。

**模型只提议，规则来裁决，网关/人来执行。**

## 12. 介绍（给用户）

她是一个有身份的存在：内核告诉她是谁，认知让她记得、想明白、慢慢长，心情让她有状态，生活参数让她在范围内调整自己。她能做的事（生图、语音、发图、收饭钱、借手机或浏览器）都是"能力"，能力和入口分开：`#画` 只是快捷键，真正做事的地方只有一处，受同一套额度和审计管。模型只能提议，规则决定能不能做，钱和安全最后一步永远由人来。
